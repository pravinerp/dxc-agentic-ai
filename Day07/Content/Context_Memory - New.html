Idea 1 · Context

Every step sends the whole chat again

A chat agent has no memory of its own between model calls. Each time it answers, the model is sent everything it needs: the rules, the chat so far and the tool results.

Tap each card

Say this: "Context is not free. Every word in the chat is paid for again at every step."
Quick check · Idea 1

Three questions

1. What does the model receive at step 5 of a chat?
Each call is a fresh request. The chat is sent again every time.
2. A chat is 40 messages long. Which costs the least per answer?
Summarising shrinks what is sent. Keeping everything is the most expensive.
3. Why can a long chat give worse answers?
More text is not always better. Old details can pull the answer off course.

The app you will use. Numbers match the steps below.
  1. You press ▶ Next script question or type a question. app.py
  2. The screen sends it to the agent with a chat id (thread_id). memory_agent.py · ask()

  6. The answer comes back, the chat is saved, and each model call becomes one bar in the chart. app.py

Idea 2 · Compaction

Summarise the old part, keep the new part

Compaction means: when the chat gets big, the agent writes a short summary of the old messages and keeps only the newest ones word for word.

Three knobs decide everything:
1. When to compact (the slider "Summarise when the chat reaches").
2. How much to keep word for word (the slider "Keep the newest messages").
3. What the summary must keep: decisions, ticket ids, open questions.

Choose the trade-off

StrategyCostRiskUse when
Keep everythingHigh, grows every turnDistraction, context limitShort chats
Keep the last few messages only (trim)LowForgets early facts silentlySimple one-question chats
Summarise the old part, keep the last fewMedium (+ one summary call)Summary may miss a detailLong support chats
Save facts in a storeLow per chatMore engineering, privacyFacts that must survive a new chat
Say this: "Compaction is a product choice. You trade a little detail for a lot less cost. Test the answers before you trust it."
Quick check · Idea 2

Three questions

1. What does compaction do?
The old part becomes a summary. The newest messages stay word for word.
2. If you set the trigger very low (for example 800 tokens), what happens?
Compacting early keeps the chat small, but each summary can lose a detail and costs one extra call.
3. Which detail must the summary keep?
Ticket ids and decisions are the facts the next answer depends on.

Idea 3 · Memory

Two kinds of memory

Short-term: one chat

Everything said in this chat thread, kept by the checkpointer. A new chat starts empty.

Like the notes on the table during one meeting.

Long-term: a store

Facts saved on purpose, kept across chats, filed per user. The agent looks them up with a tool.

Like a notebook in the drawer you open next week.

What is worth saving?

Save

Stable facts the user asked you to remember: laptop model, location, preferred contact time.

Do not save

Passwords, card numbers, health details, anything the user did not ask you to keep. Store facts, not whole transcripts.

Product choice: a notebook is fine for a few facts per user. Tickets, orders and records belong in the systems that already own them.
Quick check · Idea 3

Three questions

1. A note is saved in chat 1. Where is it found in chat 2?
Only the store keeps facts across chats. The model itself keeps nothing.
2. Which fact should NOT be saved as a note?
Payment and identity details never go into notes.
3. What is the best place for a ticket's full status?
The ticket system owns the ticket. The agent reads it with a tool, rather than keeping a copy.
