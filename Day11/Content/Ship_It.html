The one demo to remember

✅ Drop → Resume
The agent carries on. One run. One cost.
⚠️ Drop → Restart
The agent runs again. Extra cost and a possible duplicate action.
₹50,000
What if the agent was approving a refund, not reading a ticket, and a dropped connection made it run twice?
This is idempotency: the same request must never cause the same business action twice.
Honest note: Lab 14 simulates failures on purpose. It is not real enterprise infrastructure, and job state lives in Python memory, so a server restart would lose it. Production uses a database or AgentCore Runtime (Day 12).

Content 1 · Choosing the shape

Workflow or agent? Use the least agency that works

Not every AI feature needs an agent. A workflow follows steps you wrote. An agent chooses its own steps. The more it chooses, the harder it is to test and trust.

The level-of-agency scale. Most real systems sit in the middle two boxes.

Quick classify (talk in your team, 3 minutes)

Use caseYour choice: workflow, workflow + AI step, or agent?
Every night, summarise yesterday's tickets and email the manager?
Employee asks 'why is my VPN down?' in chat?
New ticket arrives, tag it with a category?
Investigate a slow database across 5 systems?
Suggested answers: nightly summary = workflow + 1 AI step · VPN chat = agent with tools (read only) · tagging = workflow + 1 AI step · database investigation = agent with limits and a human approval before any change.
Quick check

Three questions

1. A nightly report always has the same 4 steps. Best shape?
Fixed steps do not need an agent. Less agency is cheaper and easier to test.
2. A user waits while the agent works. Which screen?
A person watching wants to see progress. Long jobs they leave behind use Task.
3. Why add a human approval step?
A wrong password reset cannot be undone by the model.

Content 2 · The door

AgentCore Gateway: one door to your tools

Companies end up with many agents and many tools. A Gateway sits between them. It makes a Lambda or an API look like an MCP tool, checks who is calling, logs every call and is the place to add rules.

Without a gateway every agent is wired to every tool. With one, agents talk to ONE door, and the door talks to the tools.
💼 Say this: "Tools become shared company assets behind one controlled door, instead of copies inside every agent."
Trainer's case study: (Anil adds a real example here.)
Quick check

Three questions

1. What does a Gateway turn a Lambda into?
That is the Gateway's job: expose tools in a standard way.
2. Where do the tool's secrets live?
The agent does not hold them.
3. When is a Gateway worth it?
The more agents, the more a single door saves.

Content 3 · The shield

An agent that can act can be tricked into acting

A chatbot that is fooled says something silly. An agent that is fooled does something: resets a password, sends data, runs up a bill. So we attack our own agent before anyone else does.

Where each defence sits. Lab 12 lets you switch them on and off.
Key idea: a rule in the prompt is a request. A rule in code in front of the tool is a lock.
💼 Say this: "We assume the model can be fooled. Dangerous actions are decided by code and policy, and we run a red-team set before every release."
