Words you will meet

EventA small message the agent sends each time something happens: model started, word, tool started, tool finished, final answer.
StreamThe server pushes events to the page the moment they happen (Chat).
PollThe page asks "how is it going?" on a timer (Task).
TimeoutHow long the page waits in silence before it tells you what is happening.
Resume / restartAfter a drop: continue after the last event id you saw, or send the question again (the AI works, and you pay, twice).
Remember: users do not run Python. Give them a screen that shows progress, survives bad networks and never hides a failure.

The pieces

The agent runs in the background. It writes events into a list. The chat view keeps one connection open and receives each event as it is added. The task view never keeps a connection: it asks "what is the list now?" every few seconds.

⚡ How the streaming works (the most important idea on this page)

The idea in one line: the AI does not write its answer all at once. It writes it a few letters at a time, and we show each piece the moment it exists, instead of waiting for the whole answer.
Think of a chef sending dishes to your table one by one as they are ready, instead of making you wait until the whole meal is cooked.

The journey of one word, in 6 steps

#WhoWhat happens (plain words)
1🧠 The AI modelIt makes its answer in small pieces (a word or part of a word) and hands over each piece the moment it is ready. We ask it to work this way. That is "streaming mode".
2🤖 The AskIT agentFor every piece it receives, the agent writes a note: "new word: …". It also writes notes for the other moments: model started, tool called, tool finished, final answer.
3📒 The event listEvery note goes at the end of a numbered list: 0, 1, 2, 3 … The numbers never change and nothing is removed. This list is the "tape recording" of the whole run.
4🖥️ The serverIt keeps one connection to your browser open. About 20 times a second it checks the list: "any new note since the last one I sent?" If yes, it sends it down the open connection. If not, it waits a moment.
5🌐 Your browserThe page reads the connection bit by bit as data arrives, instead of waiting for it to finish. Each note that arrives is added to the screen straight away. That is why you see the answer grow.
6✅ The endWhen the "final answer" note arrives, the server closes the connection and the page stops the typing effect.
🔢 Why every note has a number
If the network drops after note 14 and the page is set to resume where it stopped, it reconnects and says: "my last note was 14, please continue from 15." The server looks in the list and carries on. Nothing is lost, nothing is repeated. This is the "Break it" drop test (the chaos switch cuts the line after 6 notes on purpose).
📦 Why the answer is saved in a list
The agent and the browser work at different speeds and do not talk to each other. The list is the meeting point: the agent writes to it, the server reads from it. Because the list is kept, the Task view can read the very same run later.

What the browser actually receives

The server sends plain text, in small blocks separated by an empty line. Each block has three parts: a number (id), a kind (event: token, tool_start, tool_end, final …) and the content (data). You can see exactly this in the "What the browser receives" box on the Chat tab. This method is called Server-Sent Events (SSE): one normal web request that stays open, and the server keeps adding to it.

Things you will notice (and what they mean)

You seeWhy
Words appear one by oneStep 1 to 5 above are working. This is what streaming feels like.
Offline mode types at a steady speedNo real AI is attached, so the stand-in plays the answer word by word to imitate streaming.
A long pause before the first wordThe model is still thinking or starting up (a cold start). Streaming starts only after the first piece exists. Streaming makes the wait feel shorter; it does not make the AI faster.
Odd text like <thinking>…</thinking> in the answerSome models write their private reasoning in the answer. The page shows what the model sends. A production app would filter it out before showing it.
Stream cut, then it continuesWith "resume where it stopped" the page asks to continue from its last number. With "start the question again" the AI runs twice and you pay twice.
💼 Say this to a client: "Streaming does not make the AI faster. It makes the wait feel shorter, because the user sees progress from the first second. We number every piece so a dropped connection can resume without losing or repeating anything."

Chat or task? (the question a client asks)

Chat view (stream)Task view (submit + poll)
Good forA person waiting, answer in under ~1 minuteWork that takes minutes: reports, batch jobs, anything with approval steps
User feels"It is answering me now""My job is safe; I can leave"

Breaks whenThe network drops, a proxy cuts long connectionsYou poll too fast (many requests) or too slow (stale screen)
