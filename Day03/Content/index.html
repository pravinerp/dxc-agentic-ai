Concept 1 · BASIC → INTERMEDIATE

Embeddings: meaning as numbers

An embedding model turns text into a list of numbers. Texts with similar meaning get similar numbers, even when they share no words. That one trick is how search can match meaning.

1️⃣
Text → numbers
"I'm locked out" becomes a list of 512 numbers (a vector).
2️⃣
Similar meaning → close together
"Can't sign in" gets almost the same numbers. "Printer jammed" gets very different ones.
3️⃣
Measure the closeness
A small formula (cosine similarity) turns "close" into a score we can sort by.

The meaning map explorer BASIC

Four short steps, about 6 minutes. Do them in order. Everything here is a cartoon: real Titan vectors have 512 numbers, not 2.

Idea: a computer cannot compare meanings, but it can compare numbers. The embedding model reads a sentence and writes down numbers that describe its meaning.

We show only 8 of the numbers (blue = positive, orange = negative). The bars are illustrative: they are invented to show the idea, not output from Titan. Notice that "I'm locked out" and "Can't sign in" share no words but have almost the same pattern.

Idea: if each text is a point in space, distance = difference in meaning. Here is a 2-D version: circles are helpdesk tickets, squares are KB articles. Click any point. The lines from the centre show each text's direction: the smaller the angle between two lines, the closer the meaning.
Click a point to see its 3 nearest neighbours.
Idea: we measure "close" with cosine similarity. It asks one question: "do the two arrows point the same way?" Same direction = same meaning.
Cosine (high = close)0.87
Remember: cosine near 1 = same meaning, near 0 = unrelated. Titan gives us the vectors; cosine ranks the KB articles. That is all Lab 2A needs. (Other measures exist, but we do not need them today.)
Idea: semantic search is just steps 1 to 3 in a row: embed the question, measure closeness to every KB article, sort, take the top few. This is exactly what Lab 2A makes you write.
Pick a ticket:
① Embed the ticket
② Compare with every article
One cosine score per article. Highest = best match.
③ Return the top 3
These go to the LLM later, in step ③ of the day.

keyword counts words shared with the article (what plain search does). semantic is cosine similarity. Pick "My tunnel to the office keeps dropping": keyword search finds nothing, semantic search finds the VPN article.

Concept 3 · INTERMEDIATE

RAG: retrieve, augment, generate

Put it together: find the right chunks (you built that), put them in the prompt, and let the model answer only from them.

The RAG pipeline: click Next step

1 · Load
Read the documents: KB articles, PDFs, wiki pages. (once, offline)
2 · Chunk
Cut into chunks with overlap. (Lab 2B)
3 · Embed
Titan turns each chunk into a vector. (Lab 2A, 2B)
4 · Store
Save chunks + vectors in a vector store (a list today, Chroma in Lab 2C). — indexing done —
5 · Retrieve
Embed the question, find the top-k chunks. (every question)
6 · Augment
Build a grounded prompt: context + rules + question.
7 · Generate
The LLM answers from the context, with sources, or "I don't know".
