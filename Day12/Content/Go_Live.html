Content 2 · Guard it

A rule the agent cannot argue with

Yesterday a VIP's password reset went straight through the Gateway. A rule in the prompt is a request. A policy at the Gateway is a lock: it is checked before the tool runs, and the model never sees it.

How the Gateway decides. The default answer is DENY. Only a permit rule opens a door, and a forbid rule can always shut it again.
Where a rule livesStrengthWeakness
In the promptFree, quickThe model can be talked out of it
Policy at the GatewayOne place for every agent, logged, model cannot bypassDoes not know your data; exact text only
Check inside the toolKnows the truth in the databaseHidden from the platform team; each tool repeats it
Bedrock GuardrailsFilters the words going in and out of the modelNot about which tool may run
💼 Say this: "The model can be fooled, so the 'never' rules do not live in the model. They live in a policy in front of the tool, logged on every decision, and backed by a check inside the tool."
Quick check

Three questions

1. A policy engine in Enforce mode has no rules. What happens to tool calls?
Default deny: only a permit rule opens a door.
2. A permit rule and a forbid rule both match. Result?
A matching forbid always wins.
3. 'emp-1001' got past a rule listing 'EMP-1001'. Best fix?
Two locks. The policy at the door and a strict check in the tool.
