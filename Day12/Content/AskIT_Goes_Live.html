🛠️ What we do

Run AskIT on the VM, deploy it to AWS yourself, add the company tools, see it fail and see a risky action blocked, then design AgentCore for a client.

❓ Why

A working agent is not a production agent. Clients ask about hosting, tools, monitoring and security, not about prompts.

🎓 Outcome

Your own agent hosted on AWS, version 2 with Gateway tools, a client architecture you designed, and a client line for each AgentCore feature.

👣 How

One command starts the app. Two short console forms (deploy, then add one setting). Everything else is buttons.

1. In VS Code open a terminal: Terminal > New Terminal. Type this and press Enter:

python run.py

2. The app opens in your browser. Do tabs 1 to 6 in order. Each tab tells you exactly what to click in the AWS console.

3. AWS console: sign in as your own user (user101 … user116), region N. Virginia (us-east-1).

Stuck? Click here
  • “No AWS keys”: your keys are in C:\AskIT\dxc-agentic-ai\.env. Tell the trainer.
  • Deploy failed or slow: switch on “Use the class backup Runtime” in the app's sidebar and carry on. You still do every other step.
  • “Runtime not found”: the name must be exactly askit_user1NN (small letters, underscore), region us-east-1. Then click Refresh my Runtime.
  • Port busy: close the other Streamlit window (Ctrl+C in its terminal) and run python run.py again.

✅ Adopt AgentCore when…

  • The client is on AWS and wants managed, not hand-built, infrastructure
  • Many agents must share the same tools and rules
  • Security asks for isolation, audit and central policy
  • Traffic is spiky (pay per use beats idle servers)

⚠️ Think twice when…

  • The client is standardised on another cloud
  • One tiny agent with steady traffic (a container may be simpler)
  • Strict data residency in a region where a feature is not available yet: check first
  • Cold start (a few seconds) is not acceptable: plan warm sessions

💰 Cost in one line

Hosting is the small number. Model tokens are usually the biggest line, then Runtime CPU time (billed only while working), then Gateway and policy calls (fractions of a cent). Always quote from the current AWS price page.

🩺 Client clinic: which gaps matter most?

2 minutes each. Decide in your head, then open the answer.

🏦 AskBank Ops: password resets and system access for 8,000 bank staff

Governance first (Policy: never reset privileged accounts; approval for access grants) + Identity (bank login) + Troubleshooting for audit. Go for a pilot with approvals on; no for fully automatic.

🛒 StoreHelp: shopping assistant, 20× traffic on sale days

Scale & isolation (Runtime sessions; plan for cold start) + Enterprise tools (stock and price APIs via Gateway) + a cost alarm. Go, after a peak-load test.

🏥 LabDoc: hospital report summaries for doctors

Governance (redact patient data; who may see which report) + Troubleshooting with evaluations (is the summary faithful?) + human sign-off. No-go until redaction is proven; pilot on non-patient reports.

🧪 Field lessons from this course

  • First call is slow: a few seconds for a new session, about 1 s after.
  • Agents fail “politely”: a tool error can come back as a normal reply. Read the trace, not the answer.
  • One lock is not enough: keep a check inside the tool as well as the policy.
  • Cost: model tokens are usually the biggest line; hosting is small.

❓ Ten discovery questions

  1. What job, and what does a good result look like?
  2. Which systems to read, which to change?
  3. Which actions need human approval?
  4. What must it never do?
  5. Whose permissions does it use?
  6. What data may leave the company or country?
  7. Users, questions per day, peak?
  8. How will we know it is right?
  9. Who is on call; what is the off switch?
  10. Who pays, and what is the monthly limit?
